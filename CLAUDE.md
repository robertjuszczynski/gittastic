## Commands

All commands use **pnpm** as the package manager and **Turbo** for orchestration.

```bash
# Development (all apps)
pnpm dev

# Build all
pnpm build

# Type checking
pnpm typecheck

# Lint
pnpm lint

# Desktop-specific (from apps/desktop)
pnpm --filter @gittastic/desktop dev
pnpm --filter @gittastic/desktop build
pnpm --filter @gittastic/desktop typecheck

# API-specific (from apps/api)
pnpm --filter @gittastic/api dev
pnpm --filter @gittastic/api build
```

Requires a `.env` file at the repo root with `GITHUB_CLIENT_ID` and `PORT`.

## Architecture

Turborepo monorepo with three workspaces:

- **`apps/desktop`** — Electron + React git client (the main product)
- **`apps/api`** — NestJS + Fastify backend (currently minimal)
- **`packages/types`** — Shared TypeScript types (`@gittastic/types`)

### Desktop App (`apps/desktop`)

Built with `electron-vite` which compiles three separate bundles:

| Target | Entry | Role |
|--------|-------|------|
| `main` | `src/app/main/index.ts` | Node.js process, git ops, IPC handlers |
| `preload` | `src/app/preload/` | Security bridge exposing IPC to renderer |
| `renderer` | `src/app/renderer/` | React UI (main window + onboarding window) |

#### IPC Pattern

All Main ↔ Renderer communication goes through named channels defined in `src/shared/ipc/channels.ts`. Every channel must have a handler registered in `src/main/ipc/register-ipc-handlers.ts` — an ESLint rule enforces this. Handlers live in `src/main/features/*/ipc/register-*-ipc-handlers.ts`.

Adding a new IPC channel requires:
1. Declare the channel in `src/shared/ipc/channels.ts`
2. Add the handler in the matching feature's `ipc/` directory
3. Register it in `src/main/ipc/register-ipc-handlers.ts`
4. Expose it via preload (`src/app/preload/`)

#### Feature Modules (Main Process)

`src/main/features/` — each folder owns its service + IPC handlers:

- `git/` — all git operations via `simple-git` (commits, branches, diffs, staging, stash, push/pull/fetch)
- `repositories/` — repository list management + active repo state
- `terminal/` — xterm + node-pty terminal emulation
- `settings/` — theme (dark/light)
- `onboarding/` — GitHub OAuth flow + initial setup wizard

#### Renderer

React 19 + React Router 8 app in `src/renderer/`. State via Zustand + TanStack React Query.

There are **two renderer windows**:
- Main app (`src/renderer/`) — the repository UI
- Onboarding (`src/onboarding/renderer/`) — setup wizard with its own React root

#### Shared (`src/shared/`)

Code imported by both main and renderer:
- `ipc/channels.ts` — channel name constants and payload types
- `config/env.ts` — Zod-validated environment schema
- `types/` — domain models

#### Debugging Checklist
- [ ] Verify `GITHUB_CLIENT_ID` is set in `.env` at project root
- [ ] Verify `PORT` is set in `.env` (used by env schema validation)
- [ ] Check that the `gittastic://` custom URL scheme is registered (main process)
- [ ] Check `src/main/features/onboarding/ipc/register-onboarding-ipc-handlers.ts` for the callback handler
- [ ] OAuth token is stored in `Storage` under key `git-provider-token` (Electron userData JSON)

#### Common Errors
- `ZodError on ENV parse` → Missing `GITHUB_CLIENT_ID` or `PORT` in environment
- OAuth callback not firing → Custom URL scheme (`gittastic://`) not registered with OS; check Electron `app.setAsDefaultProtocolClient`
